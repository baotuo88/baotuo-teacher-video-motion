# 草稿恢复与媒体安全应用

## 本轮范围

- 项目管理新增「草稿恢复」，以及自动应用/保存冲突时的恢复提示条。
- 对话框保留打开时的本地草稿快照，读取服务器最新版本并排展示；手机上纵向排列。
- 支持导出带源项目/版本信息的 JSON、另存独立草稿项目，不覆盖原项目、不自动跳转或丢弃输入。
- 源项目已被删除或读取失败时仍可导出；另存失败在对话框内提示。素材仅保存引用，不嵌入文件；尚未提供 JSON 导入。
- 修复保存请求期间继续输入被旧响应覆盖的问题；新输入保持未保存状态。

## 媒体安全应用规则

核查确认：当前每个项目仅允许一个 queued/running 任务，因此上一轮关于“多页任务同时提交”的判断不适用于当前实现。本轮**没有开放并行或批量付费任务**。

实际优化场景：生成第2页图片期间，用户只为第1页绑定素材；过去项目版本变化即冲突，现在可在安全条件下合入。

- 在同一 SQLite 写事务中检查从任务版本到当前版本的每一个历史版本。
- 所有非媒体内容（项目标题、主题、风格、页面顺序、每页标题/口播/要点/时长/布局）必须始终一致。
- 目标媒体字段必须始终未修改；其他媒体字段可以变化，且应用结果时保留它们。
- 修改口播、调换页面、改风格、替换目标素材、修改后再恢复都拒绝自动合入。
- 历史不完整、项目删除时保留生成结果并报告冲突，不重建项目。
- 当前版本已确认才延续确认；不把未确认草稿自动批准。
- 这是没有稳定页面 ID 时的保守策略，不宣称支持任意文本变动后的按页合并。

## 待办与边界

仍待补：历史任务分页、旧日志下载、回收站、浏览器 CI、镜像发布与上线验收。本地草稿没有后台持久化，关闭页面前应保存、导出或另存；JSON不是完整素材备份。复制草稿项目使用现有创建接口，网络响应丢失时先查看项目列表再重试，避免重复创建。未推送 Git 或发布镜像。
