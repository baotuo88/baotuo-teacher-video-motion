# 项目历史任务分页与完整日志

## 改动

- 保留现有最近100条任务的实时窗口，新增项目内「加载更早任务」，每次50条。
- 使用 `(created DESC, id DESC)` 稳定排序及项目内任务ID游标，时间相同或翻页时插入新任务不会使旧记录重复/遗漏。
- 前端合并实时任务与已加载历史，不因 SSE 刷新丢掉历史卡片；未变化的播放器节点复用。
- 每个任务支持「查看日志」：从开始按每200条继续读取，保留已读内容、滚动位置与游标；任务卡片更新也保留日志面板。
- 「下载完整日志」以请求开始时的最大事件ID为截止，分块读取并输出UTC时间；不会随运行任务无限等待，也不会在下载期间持有SQLite长读事务。
- 不在最近20条实时日志窗口内的任务明确引导手动查看/下载，不再误报等待Worker。
- 原有 `/jobs`、`/events` 返回格式保持兼容；新接口均要求管理员身份，分页游标检查项目归属，日志只读取对应任务。

## 边界

- 分页按需加载，不自动加载全部历史。大量手动加载的DOM尚未虚拟化，不宣称无限历史列表的渲染性能。
- SSE仍为完整快照方案，负载优化和压力测试未完成。
- 日志下载只包含服务器已落盘日志，不保证外部供应商返回全部内部信息；下载文件可能含业务内容，请妥善保存。
- 本轮未调用付费生成接口、未提交推送、未发布镜像。回收站、浏览器CI与统一发布验收仍待后续。
